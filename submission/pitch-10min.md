# 10분 확장 발표 원고

당시 시연은 위임 철회 뒤 통화를 유지하고 인증 표시만 거뒀다. **현재 설계는 명시적 철회 시 통화를 종료**하며, 상태 확인 불가·AI 장애는 별도로 처리한다. 아래 문구의 정책과 실행 수치는 당시 범위다.

## 6:30–7:30 위협 모델 상세

한 상태 증언자의 거짓말은 필요한 세 서명을 만들지 못합니다. 한 개 중단은 허용하지만 두 개 중단은 확인 불가로 요청을 거절합니다. 반면 정상 증언자들이 같은 잘못된 노드 상태를 읽거나 웹 코드와 신뢰할 키 목록이 교체되는 공격은 보호 범위 밖입니다. 기관 승인 시스템과 위탁 발신자의 동시 침해도 잔여 위험입니다. 그래서 이 방식을 체인 자체 증명 검증이라고 부르지 않습니다.

## 7:30–8:30 AI와 개인정보

위험 분석은 인증 여부를 바꾸지 않는 읽기 전용 내용 설명자로만 구현했습니다. 동의한 합성 전사문에서 송금·원격제어·인증번호·비밀 유지 요구를 설명하고 모델이 없으면 “규칙 기반 분석”이라고 표시합니다. 로컬 Ollama 모델의 정형 출력 연결 코드는 있지만 이번 환경의 실제 모델 추론은 미실행입니다. 고객·연락 데이터는 온체인에 올리지 않고 통화 협상 문서 원문도 로그에 저장하지 않습니다.
