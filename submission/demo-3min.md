> **2026-09-14 제출 준비 기록.** 당시 시청 사례·브라우저 직접 통화·생성 음원과 시험을 설명한다. 현재 서비스 소개·발표 순서·실환경 성공의 근거로 사용하지 않는다. 최신 내용은 [서비스 가이드](../docs/guide/README.md)를 따른다.

# 3분 데모 원고

당시 시연은 위임 철회 뒤 통화를 유지하고 인증 표시만 거뒀다. **현재 설계는 명시적 철회 시 통화를 종료**하며, 상태 확인 불가·AI 장애는 별도로 처리한다. 아래 문구의 정책과 실행 수치는 당시 범위다.

## 0:00–0:25 문제

“모의 A시청”이라는 이름은 누구나 화면에 쓸 수 있습니다. 우리가 확인하려는 것은 이름이 아니라 이 기관이 테스트 고객 Alice에게 이 목적으로 지금 연락하도록 승인했는지입니다.

## 0:25–1:05 정상 연락

기관 창에서 Alice의 서류 보완 업무와 위탁센터 C의 브라우저 키를 선택해 승인서를 발급합니다. 원장 위임이 확정되면 위탁센터 브라우저가 연락합니다. 수신 웹은 기관 승인과 증언자 4개 중 3개가 서명한 최신 권한을 확인합니다. 이어 실제 연결의 인증서와 같은 데이터 채널의 양측 새 서명을 대조한 뒤 “승인 상담 연결 확인”으로 바뀝니다. 전화의 모든 요구가 안전하다는 뜻은 아닙니다. Alice가 수락해야만 생성 음원의 패킷 전송이 시작됩니다. 서류 확인은 별도 로그인 화면으로 이동합니다.

## 1:05–1:40 사칭·복사

빠른 데모에서 같은 이름만 주장한 연락은 승인서가 없어 미확인입니다. Alice의 정상 증거를 다른 테스트 고객 Bob의 연결로 복사하면 수신자·일회성 난수·세션 결합 검사가 거절합니다. 시나리오 이름으로 빨간 화면을 만드는 것이 아니라 동일 검증 모듈에 변조 입력을 넣습니다.

## 1:40–2:25 취소·오래된 상태

기관 창에서 통화 중 원장 위임 취소를 실행합니다. 체인 확정과 증언자 관측, 3초 주기 조회 뒤 수신 화면은 `DELEGATION_NOT_ACTIVE`로 인증을 철회합니다. 정책 기본값은 통화 유지, 인증 표시 철회입니다. 이미 새로운 철회를 본 클라이언트는 과거 정상 상태으로 다시 초록색이 되지 않습니다. 당시 상태 증거는 관측 후 12초에서 거절되며 실제 경과 시간의 상한은 시계 오차 가정상 14초일 수 있었습니다.

## 2:25–3:00 공동 운영과 한계

계약은 정지 시 권한 세대를 올리고 서로 다른 2명의 EIP-712 승인 없이는 복구하지 않습니다. 과거 위임은 새 권한 세대에서 살아나지 않습니다. 블록체인의 역할은 서명 위조 방지가 아니라 여러 운영자가 변경 순서와 정지·복구 규칙을 함께 집행하는 것입니다. 이 방식은 상태 증언자를 추가 신뢰하며 체인 자체를 직접 검증하는 방식이 아닙니다. 또한 실제 기관·통신사 도입은 검증 전입니다.
