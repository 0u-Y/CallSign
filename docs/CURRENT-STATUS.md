# CallSign 한 창 촬영 데모 현황

- 확인: 2026-11-07 06:36 KST. 배포: [https://callsign-rouge.vercel.app/demo/filming](https://callsign-rouge.vercel.app/demo/filming). 실제 배포 SHA는 [build-meta](https://callsign-rouge.vercel.app/build-meta.json)에서 확인한다.
- Mac 준비: 저장소·Node·pnpm·Playwright·별도 Chrome 프로필이 필요 없다. 일반 브라우저 한 창에서 위 주소 접속 → 지정된 합성 기관 촬영자 계정으로 **한 번 로그인** → 상담원 `연락 준비`를 누를 때 Mac 마이크 허용 → 같은 화면에서 진행한다. 수신자에게 두 번째 물리 마이크 권한을 요구하지 않는다. 음향 피드백을 막으려면 이어폰을 사용한다.

## 현재 가능한 흐름

- 서버에서 새 합성 위임을 정상 API로 발급해 원장 `registered`를 확인하고, 상담원·수신자에게 같은 새 `open` 업무를 배정했다. 업무 만료는 **2026-11-08 05:03 KST**다. 기존 철회 기록·데이터·키는 보존했다. 배포 화면에서 상담원 `연락 준비` 활성화를 확인했다.
- 촬영자 세션은 서버에서 지정된 합성 상담원·수신자 계정으로만 제한 중개한다. 브라우저의 임의 역할·계정 ID로 권한을 얻을 수 없고, 상담원 세션으로 비촬영자 접속 시 통합 화면을 열지 못했다. 기관·상담원·수신자 UI는 한 창에 있지만 각자의 controller·WebRTC 연결과 서버 권한 검사를 사용한다. 공동 승인자의 독립 서명 절차는 그대로 둔다.
- 수신자는 `recvonly` WebRTC로 상담원 remote track을 받는다. PBX signaling은 브라우저의 로컬 네트워크 접근 차단을 피하도록 Vercel의 같은 origin `/api/pbx`에서 중계한다. 서버는 여전히 실제 PBX와 연결한다.
- Space는 보이는 역할의 다음 실제 버튼을 누른다: 상담원 준비 → 수신자 준비 → 발신 → 수락. 동의·철회·종료는 수신자가 화면에서 직접 조작한다. F는 촬영 안내 표시만 전환한다. 이전 화면의 브라우저 키로 승인된 시도는 자동 재사용하지 않고 `이전 시도 종료 · 새로 준비`를 제공한다.

## 이번에 실제 확인한 것과 한계

- 새 브라우저에서 촬영자 1회 로그인 후 두 역할 화면 진입, 비촬영자 차단, 1440·1920·390px 배치와 버튼 잘림 방지, 버튼 포커스 후 Space 두 번에 요청 1회, 타입·빌드·관련 검사 및 필수 CI를 확인했다. 서버 코드와 Vercel 화면을 각각 갱신했다.
- 설치 Chromium의 **합성 마이크/합성 한국어 음성**으로 실제 상담원 준비 → 수신자 준비 → PBX 발신 → 수락을 실행했고, 양측 통화 활성 및 수신자 remote audio track `live`를 확인했다. 이는 사용자의 Mac 마이크 리허설 결과가 아니다.
- 수신자가 안내문을 확인하고 분석에 동의한 뒤, 합성 음원을 통화 송신 경로로 전달했다. 새 승인 한도에서 STT 연결 **1/2**, STT **9/120초**, LLM 요청 **1/8**을 사용했다. 위험 근거 결과는 화면에서 확인되지 않았고 분석 상태가 `unavailable`로 바뀌었다. 철회 시 진행 중 LLM 요청의 취소 로그가 남아, 모델 실패와 철회 취소를 분리해 추가 확인해야 한다. **실제 위험 분석 완료는 검증되지 않았다.** 사용자 촬영용 제공자 연결 1회가 남아 있으며 한 연결은 STT 최대 60초·LLM 최대 4회다. 현재 한도 만료는 **2026-11-07 22:02 KST**다.
- 기관은 지금 정지하지 않았다. 공동 복구의 새 정지·동일 요청·두 독립 서명·명령별 Witness 확정은 실행하지 않았다. 관리 화면의 노드 health만으로 Witness 확정이라고 표시하지 않는다.

## 촬영 조작과 실패 시 확인

1. 위 주소에서 촬영자 로그인. 상담원 카드의 `연락 준비`를 눌러 Mac 마이크 권한을 허용한다. 수신자 휴대폰의 `연락 받을 준비` → 상담원 `발신` → 수신자 `수락` 순서로 조작하거나, 가능한 단계에서 Space를 누른다.
2. 통화 중 상담원이 Mac 마이크로 직접 말한다. 수신자는 실제 음성 분석 안내를 읽고 키패드에서 1번 동의 또는 2번 미동의를 선택한다. 결과가 나오면 전사·근거 발언·오류 상태를 확인한다. 철회와 종료는 각 화면에서 직접 누른다.
3. 실패하면 해당 역할의 화면 오류와 `연결 준비 상세`를 확인한다. 이전 승인 시도가 남았다면 `이전 시도 종료 · 새로 준비`를 누른다. 세션 만료는 촬영자 로그인부터 다시 진행한다. 분석이 `unavailable`이면 미탐지나 성공으로 촬영하지 않는다.

남은 차단: 실제 Mac 마이크 리허설은 사용자가 진행한다. 합성 음성 시험에서 STT 이후 위험 분석 결과가 미확인이라, 추가 유료 연결 없이 서버·브라우저의 기존 비밀 없는 진단 근거로 실패 지점을 더 좁혀야 한다. 공동 복구는 별도 정지 요청과 같은 복구 요청의 독립 승인 준비 뒤에만 실행한다.
