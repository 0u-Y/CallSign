## 실제 로그인 관측

보호 파일을 읽어 기관·상담원·수신자를 독립 browser context에서 각각 실제 Keycloak 폼으로 로그인했다. 쿠키·세션을 주입하지 않았다. 네트워크 기록은 host/path/status와 쿠키 존재 여부·속성만 보관하며 값·코드·토큰·비밀번호는 저장하지 않았다. 캡처는 로그인 폼 제출 이후에만 했다.

수정 전 세 역할 모두 callback 200 → auth/me 200 → workspace 200이었다. 첫 비로그인 auth/me 401은 정상적인 로그인 전 응답이다. 세션 쿠키는 Vercel host의 `ip_session`, Secure/HttpOnly/SameSite=Strict/path=/였으며 후속 요청에 전달됐다. 반면 최초 요청 `/demo/work`가 `/service`로 돌아가는 문제는 재현했다.

수정: 현재 탭의 sessionStorage에 허용된 원래 경로를 OIDC state와 함께 저장하고, 성공 callback 뒤 일치한 요청의 경로를 한 번만 소비한다. 10분 만료, 외부 URL·변형 경로·다른 state 거부. 서버 callback URI·쿠키 설정·프록시를 변경하지 않는다. 공식 업무 callback은 기존 `/official`로 간다.

이 검사는 **서버 호스트의 공개 URL Chromium**이다. 사용자의 외부 PC/클라우드 브라우저에서 이전에 관측한 로그인 실패는 이번 환경에서 재현되지 않았다. 클라우드 제한 또는 제품 결함 중 하나로 단정할 증거가 없다. 필요 시 해당 환경에서 callback/me/workspace 상태 코드와 쿠키 차단 사유를 값 없이 추가 관측해야 한다.

## 위임·통화 선택의 정확한 한계

`/v3/workspace`는 위임 digest·원장 상태·콜센터 ID만 반환한다. 위임 유효기간, 키·epoch·scope 원문은 없다. 따라서 이번 frontend는 **등록 후보**라고 표시하며 유효 위임이라고 확정하지 않는다. 서버 `ServiceAuthority.delegation`의 기간·기관·콜센터 키·정책·epoch 검증을 보존한다. 기간·scope까지 준비 버튼 누르기 전에 판정하려면 해당 서버 검증 결과를 읽기 전용 계약으로 제공하는 후속 작업이 필요하다. frontend가 없는 값을 추측하지 않는다.

업무 상세의 ‘철회됨 · 원장 등록됨’은 한 위임의 모순 상태가 아니라 같은 콜센터의 여러 위임을 한 문자열로 합친 표시였다. 이제 digest별 상태와 선택 가능 여부를 분리했다. 선택한 업무와 다른 통화나 종료된 시도를 명시적으로 넘기면 다른 시도로 조용히 대체하지 않고 재선택을 요구한다. 서버 최종 권한 검사는 그대로다.

## Space와 역할별 촬영 순서

1. 기관·상담원·수신자를 **독립 브라우저 프로필/context**로 실제 로그인한다. 같은 origin 탭 분리로 대신하지 않는다. 필요한 세 창을 촬영 데스크톱에 배치하거나 역할별 영상을 편집한다. 이 웹은 다른 창의 세션에 명령을 주입하는 다중 역할 관리자 기능을 제공하지 않는다.
2. 기관: `/demo/work`에서 진행 중 업무·대상·담당자·콜센터·기간을 확인한다. 새 업무·취소·위임 변경은 이번 읽기 승인 범위 밖이다.
3. 상담원: 배정 업무 상세 → 연락 검증 이동. 준비가 가능한 업무/위임을 선택한다. **여기까지는 읽기 검사**다. Space/연락 준비는 마이크와 승인 요청을 수행하므로 촬영 실행 승인을 받은 뒤 누른다.
4. 수신자: 자신의 같은 업무·통화 시도를 선택해 연락 받을 준비를 한다. 상담원 창의 Space는 상담원의 실제 발신 버튼, 수신자 창의 Space는 수신자의 실제 수락 버튼으로 이어진다. 다른 역할 행동이 필요하면 대기 문구를 보여준다.
5. 연결 후 수신자는 처리 안내를 읽고 음성 안내 종료를 기다린다. 키패드 2는 미동의, 1은 별도 승인된 실제 분석, 9는 로컬 안내 재생이다. Space가 1번을 누르지 않는다. 제공자 OFF이면 동의 버튼을 통해 성공을 만들지 않는다.
6. 상대 발언·전사·분석 결과를 실제 이벤트로 확인한다. 분석 장면 탭 선택은 촬영 안내만 바꾸며 음원·위험 결과를 만들지 않는다. 상담원 창에 수신자 비공개 전사·분석 동의를 새로 노출하지 않는다.
7. 철회·종료는 해당 역할의 실제 버튼으로 수행한다. F는 제목·운영 조작·Space 안내를 숨기거나 복원할 뿐 통화/분석 상태를 바꾸지 않는다. 종료 버튼은 숨기지 않는다.
8. 공동 관리 촬영은 별도 권한/서명과 승인된 쓰기 범위에서만 수행한다. 기존 통화/위임이 복구 후 자동 부활한다고 표현하지 않는다.

## 남은 실제 실행 승인

먼저 유료 제공자를 사용하지 않는 **1회·최대 60초 공개 통화**가 필요하다. 정확한 진행 중 업무 한 건에서 독립 상담원/수신자 두 창의 준비(승인·마이크·PBX 등록), Space 발신/수락, 분석 미동의, 통화 중 페이지 이동, 종료를 확인한다. 업무 생성·취소·기관 정지·복구·유료 AI는 포함하지 않는다. 마이크 대신 승인된 합성 음원/입력을 사용할지는 실행 전에 정한다. 운영 기한·stop·자원 상태를 다시 확인하고 중단 절차를 우회하지 않는다.

실제 AI 분석→철회→늦은 결과 차단 검증은 별도다. 남아 있는 유료 제공자 예산을 이 UI 작업이 승계하거나 소진하지 않는다. 모델/STT 요청 수·음성 길이·비용·기한을 정한 유효 승인이 있어야 한다. 현재 UI 구현·배포 성공을 공개 음성/AI 전체 완료라고 보고하지 않는다.
