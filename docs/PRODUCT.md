# Product

CallSign는 전화를 받은 사람이 상대의 표시 이름을 믿는 대신 다음 세 판단을 구분하게 합니다.

1. **기관 승인:** 기관 업무 승인키가 이 수신자·목적·위임에 대한 개별 연락 승인서를 서명했는가.
2. **발신 권한:** 현재 epoch에서 해당 gateway 키와 목적이 위임되어 있고 정지·취소·만료되지 않았는가.
3. **현재 연결:** 승인서가 가리키는 양측 SDP fingerprint와 실제 연결의 remote DTLS certificate, 같은 datachannel의 상호 challenge가 일치하는가.

통화 내용의 안전성은 별도 판단이며, 서류 보완은 `/official`에서 다시 로그인하고 task owner를 검사한다. 전화의 opaque ID나 승인서만으로 업무 객체에 접근할 수 없다.

## 데모 사용자 흐름

- 모의 A시청 담당자: 사전 생성 업무 선택 → 위탁센터 C의 공개키 선택 → 승인 발급 → 필요 시 원장 위임 취소.
- 위탁센터 C: 브라우저 non-extractable Ed25519 키 생성 → 공개키 등록 → 승인 연락 선택 → 별도 창의 Alice에게 WebRTC 발신.
- Alice: 테스트 세션 enrollment → 연락 수신 → 승인/위임/연결 검증 결과 확인 → 명시적 수락 → 공식 업무에서 재로그인.
- 공동 승인자: 2-of-3 등록·복구 규칙을 계약과 Foundry 테스트로 검증. 현재 운영 UI의 서명 기록과 실제 복구 제출은 분리되어 있다.

## 성공 기준

정상 화면이 초록색으로 보이는 것만이 아니라, proof의 한 필드·수신자·nonce·fingerprint를 바꾸거나 위임을 취소하고 witness를 중단했을 때 해당 검사에서 fail-closed 되는 것을 실제 결과로 남기는 것이다.
