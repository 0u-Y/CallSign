# 초기 시청 시연의 제품 설계

**2026-09-14의 과거 설계 기록**이다. 현재 제품 기준은 [루트 제품 문서](../PRODUCT.md), 사용자 설명은 [서비스 개요](guide/01-SERVICE-OVERVIEW.md)를 따른다. 초기 코드는 통신 형식 `version=1`로 보존하며 현재 서비스 완료의 근거로 사용하지 않는다.

## 당시 확인하려던 세 판단

1. **기관 승인:** 기관이 특정 수신자·목적·위탁 발신자에 대한 개별 연락 승인서에 서명했는가.
2. **발신 권한:** 현재 권한 세대(epoch)에서 그 발신키와 목적이 위임돼 있고 정지·철회·만료되지 않았는가.
3. **현재 연결:** 승인서의 통화 협상 문서(SDP) 지문과 실제 연결의 원격 인증서가 맞고, 같은 데이터 채널에서 양측이 새로운 서명 요청에 답했는가.

내용 안전성은 별도 판단이다. 서류 보완은 `/official`에서 다시 로그인하고 업무 소유자를 검사한다. 연락 승인서나 추측하기 어려운 업무 ID만으로 공식 업무 접근 권한을 주지 않는다.

## 당시 사용자 흐름

- 모의 A시청 담당자: 사전 생성 업무 선택 → 위탁센터 공개키 선택 → 승인 발급 → 필요 시 원장 위임 철회.
- 위탁센터: 브라우저에서 외부로 추출할 수 없는 Ed25519 키 생성 → 공개키 등록 → 승인 연락 선택 → 테스트 수신자 Alice에게 직접 웹 통화.
- Alice: 테스트 계정과 통화용 공개키 연결 → 수신 → 승인/위임/연결 검증 → 명시 수락 → 공식 업무 재로그인.
- 공동 승인자: 3명 중 2명이 기관 등록·복구를 승인. 화면의 승인 기록과 실제 계약 실행은 구별한다.

## 당시 완료 판단과 현재 차이

증거의 수신자·일회성 난수·인증서 지문을 바꾸거나 위임을 철회했을 때 실제 검증이 거절하는지 시험했다. 당시에는 통화 중 철회 후 인증 표시만 거두고 통화를 유지했다. **현재 목표는 명시적 철회 시 해당 통화 종료**, 재사용 업무 위임·개별 승인 분리·원격 음성 분석·Asterisk 교환기 통화다. [현재 구현과 남은 작업](guide/05-IMPLEMENTATION-STATUS.md)을 별도로 확인한다.
