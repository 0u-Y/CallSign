# 현재 구현의 한계

기준일: 2026-10-27. [현재 구현·검증 현황](guide/05-IMPLEMENTATION-STATUS.md)과 [개발 기록](FINALS-IMPLEMENTATION-PLAN.md#service-20261027)을 함께 갱신한다. ‘부분 구현’은 코드가 남은 상태이며 ‘실환경 미검증’과 다르다.

## 현재 서비스

- **교환기 제품 경로 미완성.** Asterisk 채널 조회·음소거·브리지·서명 API와 브라우저 SIP 모듈을 작성했다. 역할 화면·사건 구독·기한 감시·철회/로그아웃 자동 회수·실제 설정·배포·전체 시험이 남아 있다. 이전 `MediaEdgeAdapter`가 호출하는 외부 서버는 구현 근거가 아니다.
- **통화 수명 전환 미완성.** 추가 서버는 120초 최초 연결과 갱신형 통화 유지 허가를 분리하지만 기존 직접 통화 화면은 짧은 승인 만료에 연결을 종료한다. 새 화면·양측 연결 재확인·갱신·재시작 복구가 필요하다. 30초 유지 허가·최대 4시간은 임시 코드 정책이며 확정 운영값·실측값이 아니다.
- **DID 없는 전체 경로 미완성.** 등록 주소·키 기반 발급 API는 있으나 키 준비·신뢰 설정 생성·기본 화면에는 DID 전제가 남아 있다. DID(분산 식별자)는 확정 설계의 기본 필수 조건이 아니다.
- **원장 작업 재처리 미구현.** 후속 작업 보관함(outbox) 저장 코드만으로 등록·철회 트랜잭션의 제출·응답 유실·재시작 복구를 보장하지 않는다. 처리기·이벤트 읽기 위치·실제 상태 재대조가 필요하다.
- **DB 동시성·최소 권한 미검증.** 기관별 JSONB 행 잠금·공통 일회 사용 제약·별도 DB 역할 코드를 작성했으나 schema 적용·GRANT·취소/사용 경합은 실제 PostgreSQL에서 시험하지 않았다. 행 크기·잠금 대기·감사 보관·삭제 정책도 필요하다.
- **전체 비용 통제 미완성.** 호출별 시간·크기·횟수 제한과 공유 사용량 예약 코드는 있으나 실제 병렬 DB 예약·제공자 사용량 정산·과금 유실 복구는 미검증/미완성이다. 계정 예산·보관 설정은 제공자 측에서도 준비해야 한다.
- **AI 품질 미측정.** 부정·인용·자기정정 규칙은 일부 표현만 처리한다. 실제 한국어 전사·탐지율·오탐·미탐·지연을 측정하지 않았다. 재연결은 새 스트림·재동의를 요구하고 누락 구간 복구를 보장하지 않는다. 분석 불가·경고 없음은 안전 판정이 아니다.
- **로그인·재인증 운영 미완성.** OIDC(외부 로그인 표준) 흐름과 일반/공식 용도 분리는 코드가 있으나 실제 로그인 제공자·DB 통합은 미검증이다. 로그인 진행 상태가 메모리여서 재시작·다중 인스턴스에서는 다시 로그인해야 한다. 주요 작업 재인증 정책도 남아 있다.
- **복원 최신성 보장 미완성.** DB에 최고 관측 상태와 복원 검토 전 사용 차단 코드를 추가했다. 복원 대상 밖 최신 기준·철회/사용 이력 대조·안전한 차단 해제 도구는 없다. 내부 DB·체인을 모두 과거로 되돌렸을 때 자체 일치만으로 최신성을 알 수 없다.
- **운영 배포 미검증.** Terraform은 초기화·검증·계획·적용하지 않았고 Compose 정적 파싱은 실제 이미지·설정·기동을 보장하지 않는다. 교환기 배포 설정은 외부 미디어 서버 가정이 남아 수정이 필요하다. 백업 도구는 DB 덤프이며 체인·키·신뢰 설정까지 일관된 전체 백업은 아니다.

현재 PostgreSQL·로그인 제공자·서비스 연결·Besu·상태 증언자·브라우저/마이크·TURN·교환기·외부 AI·GCP를 실행한 통합 검증은 없다. 체인 헤더·확정 서명·계정/저장 증명을 직접 확인하는 `native-qbft` 확장은 미구현이며 기본 서비스 완료 조건과 별도다.

## 보존한 초기 시연의 한계와 정책 차이

아래는 **2026-09-14 코드·시험**의 범위다. 현재 서비스가 통과한 결과나 운영 절차로 사용하지 않는다.

- Chromium 153·같은 컴퓨터에서의 직접 통화·실제 원격 인증서 관측만 검증했다. Firefox/Safari·실제 모바일·TURN·여러 기기는 미검증이었다.
- 네 노드·증언자는 키·프로세스·조회 서버가 나뉘었으나 같은 호스트·운영자여서 독립 기관 운영의 증거가 아니었다.
- 시연은 승인마다 새 위임을 생성하고 철회 후 통화는 유지한 채 인증 표시만 철회했다. **현재 목표는 위임 재사용과 명시적 철회 시 통화 종료**다.
- 당시 활성 화면은 3초 주기로 상태를 조회했고 마지막 기록의 취소 요청→표시 철회는 6.691초였다. 현재 체인 확정 후 5초 목표와 측정 시작점·코드가 다르다. 만료 뒤 화면 타이머 지연의 반복 측정도 하지 않았다.
- 공동 복구에서 관리자·정지키를 바꿨지만 기관 승인용 Ed25519 키는 유지했다. 새 승인키 교체 성공의 증거로 사용할 수 없다.
- 시연용 신뢰 설정을 다시 생성하는 `demo:up`은 초기화 도구다. 현재 배포의 일반 재시작·복원 명령이 아니다.
- 합성 전사문·규칙과 선택 Ollama 연결 코드는 있었으나 실제 모델 추론은 하지 않았다.
- 당시 Vercel 공개 화면은 고정 시험 데이터·브라우저 내 검증·저장된 로컬 증거를 보여주는 미리보기였다. 원격 PostgreSQL·Besu·분리 브라우저 전체 서비스는 아니었으며 현재 공개 주소·자동 배포 연결은 재확인하지 않았다.
