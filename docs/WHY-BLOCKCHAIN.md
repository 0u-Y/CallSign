# Why blockchain

제품 가치는 수신자별 승인과 실제 연결 검증, 공식 업무 분리에서 나온다. 이것들은 중앙 시스템에서도 구현할 수 있다. 원장의 증분 가설은 **서로 독립된 기관이 권한 변경 순서와 정지·복구 규칙을 공동 집행하고, 한 상태 운영자의 독단적 응답에 덜 의존해야 하는 상황**이다.

| 조건 | C1 중앙 상태 + 기관 서명 | C2 기관별 서명 문서 | B QBFT + P0 witness |
|---|---|---|---|
| 승인서·session·WebRTC 검증 | 동일하게 가능 | 동일하게 가능 | 동일하게 가능 |
| 권한 없는 타 기관 수정 | 접근통제로 거절 | 기관 서명으로 거절 | 계약 권한으로 거절 |
| 상태 응답자 1곳의 거짓말 | 중앙 운영자 신뢰 | 최신 signed document 전달 필요 | 고정 witness 3-of-4가 같은 상태에 서명해야 함 |
| 정지·복구 순서 | 동일 quorum 로직을 중앙이 운영 | 기관별 version 조정 필요 | 계약 epoch와 QBFT ordering |
| 가용성 | 구성요소 최소 | 기관별 전달 경로 필요 | witness 1개 중단 허용, 2개 중단 시 fail-closed |
| 비용 | 가장 낮음 | 중간 | validator 4 + witness 4 운영 |

C1을 일부러 취약하게 만들지 않았고 C2 투명성 로그의 inclusion/consistency proof는 구현하지 않았다. B도 네이티브 light client가 아니라 별도 상태 증언자 집합을 추가로 신뢰하는 P0 프로파일이다. 실제 기관이 공동 운영과 비용을 받아들일지는 검증되지 않았다.
