# ADR 0002: 업무 기반 승인·키 분리·통화 수명

ADR은 설계 결정과 이유를 남기는 기록이다. 2026-10-26 결정을 바탕으로 하며 **2026-10-27 확정 변경**을 반영한다. 현재 구현 상태·완료 조건은 [전체 명세](../MASTER-DEVELOPMENT-SPEC.md), 연결 상태는 [현황표](../guide/05-IMPLEMENTATION-STATUS.md)를 따른다.

## 유지하는 결정

1. **기존 스택과 의존성 재사용.** TypeScript·Fastify·React·PostgreSQL·Solidity·Besu를 유지한다. 모의 이상거래 시스템을 실제 금융기관 연동으로 표현하지 않는다.
2. **업무가 권한의 시작점.** 기관·역할·수신자·상담원·콜센터 할당을 서버에서 확인한다. 기관별 업무를 한 JSONB 행에 저장하고 `FOR UPDATE`로 취소·사용·키 변경 순서를 정한다. 규모가 커지면 행 크기·잠금 대기를 측정해 분리해야 한다.
3. **기관·콜센터 키를 브라우저와 플랫폼에서 분리.** Platform은 요청 중계, Issuer Gateway는 기관 승인, Sender Agent는 콜센터 서명을 맡는다. 기관 업무 쓰기 DB 계정과 로그인 계정도 분리한다. 공동 관리 승인자는 각자 자기 키 하나만 가진다.
4. **위임 증서와 개별 연락 승인 분리.** VC는 재사용 가능한 업무 위임이며 고객별 승인과 다르다. 정책·키 버전·권한 세대를 결합하고 VC 내용 해시를 기존 권한 계약에 등록한다. 매 통화마다 새 위임 트랜잭션을 만들지 않는다.
5. **영수증을 저장 확정 전에 서명해 함께 보관.** 같은 승인·세션 결합의 재시도는 동일한 저장 JWS를 반환한다. 취소가 먼저면 사용을 거절하고, 사용 뒤 취소돼도 현재 상태에서는 취소를 반영한다. 실제 PostgreSQL 보장은 통합 시험 전 미검증이다.
6. **각 증언자의 블록 후보를 교차 확인.** 한 조회 서버나 가장 느린 노드에 의존하지 않는다. 같은 내용의 유효 서명 3개를 모으면 나머지를 취소한다. 오래된 블록에 새 서명을 붙여 최신성 기한을 늘리지 않는다.
7. **수락과 분석 동의를 분리.** 통화 수락 전 마이크를 송신하지 않는다. 분석 동의 뒤 상대방 수신 음성만 전송하고 제공자 장애를 안전 판정으로 바꾸지 않는다. 종료·오류·철회 시 자원을 정리한다.
8. **실행 검증은 별도 승인.** 네트워크 없는 `pnpm light`와 통합·체인·미디어·성능 검증을 분리한다. 현재 단계에서 무거운 실행 차단을 해제하지 않는다.

## 변경한 결정과 이행 상태

| 이전 설계 | 확정 변경·이유 | 현재 남은 연결 |
|---|---|---|
| DID 문서 조회 필수 | 등록 기관·콜센터 URI와 키를 기본으로 사용. 고객 DID·지갑 불필요 | 키 준비·신뢰 설정 생성·기본 화면의 DID 전제 제거 |
| 짧은 승인 만료에 통화 전체 종속 | 120초 최초 연결 기한과 갱신형 통화 유지 허가 분리 | 양측 현재 연결 재확인·수락/갱신 UI·자동 종료 전파 |
| 별도 외부 Media Edge 서버 가정 | Asterisk가 웹 통화의 음성 종단·브리지를 담당 | 실제 설정·이미지·사건 처리·회수·배포·통합 시험 |
| 체인 자체 증명 확장의 완료 범위 혼재 | 별도 후속 확장으로 분리. 현재 증언자 검증과 동일하다고 설명하지 않음 | 확장을 채택할 때 별도 구현·독립 벡터·Besu 대조 검증 |

기존 초기 시연 코드와 시험 증거는 보존한다. 현재 직접 통화 형식과 추가 서버 형식은 [통신 규약](../PROTOCOL.md#protocol-profiles)에서 명시적으로 구별하며 이전 형식으로 자동 우회하지 않는다.

## 2026-10-27 실행 전 경계 보강

- 주요 공식 목록/정책 변경은 새 `ServiceRegistry`의 EIP-712 2-of-3 명령으로 고정했다. 구 관리자+한 승인자 경로를 새 계약에서 거절한다. proxy가 없으므로 기존 배포를 수정한 척하지 않고 새 주소·code hash·초기 policyHash·trust로 명시 이행한다.
- 정책 hash 변경은 질문/금지 요구/위임 범위가 바뀌므로 권한 세대를 올려 구 VC/통화를 무효화한다. 현재 공식 경로 `/official`의 표시명 변경은 권한 범위가 같아 세대를 유지한다. 확정 event/state·최신 증언 전에는 활성화하지 않는다.
- 내부 계정 등록은 기존 OIDC issuer/subject와 연결하며 새 비밀번호/IdP 관리 제품을 추가하지 않는다. 계정 SQL 변경과 권한 checkpoint를 같은 DB transaction에 넣고 일반 관리자는 공동 승인자 집합을 만들지 못한다.
- 소비만 anchor에 묶으면 옛 계정 권한이 일관된 백업에서 살아날 수 있다. 계정/키/정책 및 취소/회수 사건도 metadata checkpoint로 남긴다. 분산 CAS/DB commit 불명은 자동 복구하지 않고 새 기준 없는 구 DB를 자동 채택하지 않는다.
- 긴 RPC 서명 준비는 서명자별 영속 lease, 전체 journal 검사는 읽기 snapshot을 쓴다. 결과를 반영하기 직전에 소유권/기한·head를 다시 확인한다. 잠금을 줄이되 외부 exactly-once를 주장하지 않는다.
- 외부 메시징 공급자는 미선택이므로 내부 영속 웹 알림을 먼저 연결했다. 새로운 결제/메시징 제품을 임의 채택하지 않는다. 실제 환경 검증은 계속 별도 실행 허가 뒤에 한다.
