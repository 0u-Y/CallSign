# CallSign 실제 음성 촬영 준비

공개 주소: https://callsign-rouge.vercel.app/demo/call  
촬영 리허설·영상 녹화: 촬영자 직접 수행. 이 문서는 기술 준비와 조작 순서만 안내한다.

## 1. 촬영 노트북 준비

Node 22, 저장소의 설치된 pnpm 의존성·Chromium, 운영자가 제공한 보호 합성 계정 파일이 필요하다. **서버에서 만든 세션·마이크 권한은 촬영 노트북으로 옮겨지지 않는다.** 계정 파일은 노트북의 소유자 전용 0600 경로에 두고 화면 공유·Git·URL에 넣지 않는다.

```bash
CALLSIGN_RECORDING_PREP_ENABLED=1 pnpm demo:prepare --credentials /private/path/login-credentials.protected.json
```

로컬 `CallSign 촬영 준비` 창에서 **촬영 세션 준비**를 누른다. 기관·상담원·수신자는 독립 Chromium 프로필로 열린다. 기존 유효 세션은 재사용하며 상담원·수신자 창에 같은 진행 중 업무를 선택한다. 로그인과 업무 선택이 끝나도 `연락 준비`가 비활성이면 **촬영 준비 완료가 아니다**. 준비 창에 표시된 원인을 확인하고, 필요한 업무·위임 상태를 기관 창에서 검토한 뒤 다시 누른다. 공개 웹에는 무인증 관리자 로그인 기능이 없다.

2026-11-07 읽기 전용 확인 당시 상담원에게 배정된 유효기간 내 업무 두 건의 위임 기록은 모두 `revoked`였고, 이전 통화 시도는 `failed`/`ended`였다. 그래서 `연락 준비`가 `등록된 위임이 없습니다`로 비활성화됐다. **종료된 시도를 재사용하지 않는다.** 기관의 권한 있는 담당자가 실제 콜센터 위임을 정상 절차로 발급하고 원장 등록을 확인해야 한다. 기존 업무가 만료됐으면 새 업무를 정상 등록한다. 이 작업은 촬영 준비 버튼이 대신 실행하지 않는다. 실제 권한 변경이 허가되지 않았으면 여기서 멈추고 기존 상태를 보존한다.

## 2. 역할별 창과 음향

- **기관 창:** `/demo/work`에서 업무·담당자·콜센터·위임 상태를 확인한다. `/demo/governance`에서 정지/복구의 현재 단계와 근거를 확인한다.
- **상담원 창:** `/demo/call`에서 `마이크 선택·입력 확인`을 연다. `마이크 권한·입력 확인`을 명시적으로 누른 뒤 입력 장치를 고른다. 2초 측정의 dBFS 값은 실제 마이크 입력이며 **상대방 수신·STT 성공 증거는 아니다**. 선택한 장치는 실제 WebRTC/PBX controller가 통화 준비 때 다시 연다. 권한 거부·장치 없음·선택 장치 불일치가 표시되면 브라우저 권한과 장치 설정을 확인한다.
- **수신자 창:** 같은 업무와 통화 시도를 확인한다. 수신자 마이크의 음소거와 상담원 음성의 스피커/이어폰 재생은 별개다. 한 노트북에서 두 창을 사용할 때는 **이어폰을 끼고 수신자 마이크를 음소거**해 피드백을 피한다. 스피커 출력 선택이 지원되지 않으면 운영체제의 출력 장치를 사용한다.

마이크 권한·분석 동의·발신은 준비 버튼이 자동으로 실행하지 않는다. `연락 준비`는 실제 업무/위임 확인 → 새 시도·개별 승인 → 마이크/PBX 준비를 시작한다. 양쪽이 **같은 시도**를 고른 뒤 상담원이 발신하고 수신자가 수락한다. `연결 READY`나 마이크 레벨만으로 양쪽 음성 수신·STT를 성공 판정하지 않는다. 통화 중에는 두 창의 실제 수신/송신 상태를 확인한다.

## 3. 다섯 장면의 조작 순서

1. **정상 연락:** 기관 업무와 위임 확인 → 상담원 `연락 준비` → 수신자 `연락 받을 준비` → 상담원 발신 → 수신자 수락 → 두 창의 권한·연결 상태 확인. 실제 통화가 확인되면 상담원이 노트북 마이크로 말한다.
2. **위험 요구:** 수신자가 분석 처리 안내를 읽고 키패드로 동의한다. 상담원이 실제 마이크로 위험 요구 문장을 말한다. 수신자 화면의 상대 음성 전사 **final**과 위험 근거 발언·설명이 나타나는지 확인한다. 분석 중·무음·판단 불가·제공자 OFF·실패는 각각 그대로 설명한다. 화면의 원문 일치만으로 판단 정확도를 보장하지 않는다.
3. **동의 철회:** 수신자가 분석 동의를 철회한다. 새 음성 전송과 뒤늦은 분석 결과 표시가 중단되는지, 일반 통화는 유지되는지 확인한다. 이미 제공자에게 보낸 정보가 삭제됐다고 설명하지 않는다.
4. **기관 정지:** 허가된 기관 담당자가 `/demo/governance`에서 정지 요청을 검토·실행한다. 요청 접수, 실제 권한 차단, 진행 통화 종료와 PBX 회수 관측을 구분한다. 실행 범위가 없으면 버튼을 제출하지 않는다.
5. **공동 복구:** 실제로 정지된 기관에 대해 같은 복구 요청을 서로 다른 승인자들이 독립 서명한다. 검증한 서명 2개 이상으로 제출한 뒤 원장 확정 → Witness 확인 → 서비스 적용을 각각 확인한다. 근거가 없는 단계는 미확인으로 둔다. 복구 후에는 **새 위임·새 업무·새 승인**으로 연락하며 종료된 통화·취소 업무는 되살리지 않는다.

F/`촬영 화면`은 화면 표시만 바꾼다. Space는 현재 역할에서 허용된 실제 다음 조작에만 연결되며 분석 동의·공동 서명을 대신하지 않는다. Escape는 안내·키패드·촬영 편집 상태를 닫거나 되돌릴 때 사용한다. 통화 종료·분석 철회·오류·제공자 OFF는 촬영 중에도 확인한다.

## 4. 문제가 생길 때

- **준비 창 ‘등록된 위임이 없습니다’:** 기관 창의 콜센터 위임 기록·원장 등록 상태를 확인한다. 철회된 증서를 UI에서 유효 처리하지 않는다.
- **업무 만료/시도 종료:** 기관에서 유효 업무를 정상 생성하고 상담원·수신자가 새 시도를 선택한다. 전 시도의 단기키·승인은 재사용하지 않는다.
- **마이크 권한 거부/장치 없음:** 브라우저·OS 입력 권한을 확인하고 준비 화면에서 다시 측정한다. 다른 프로필의 권한은 공유되지 않는다.
- **통화 연결 실패:** 상담원·수신자가 같은 시도인지, 양쪽 마이크/PBX 등록·WebRTC 상태와 실제 권한 증거를 상세 패널에서 확인한다. 이전 실패를 성공처럼 유지하지 않는다.
- **전사 없음:** 수신자의 실제 동의, remote audio 수신, MediaRecorder WebM/Opus 지원, `/api/v3/audio` 연결, 제공자 상태와 입력 한도를 구분해 확인한다. 소켓 READY만으로 음성 청크 전송을 추정하지 않는다.
- **분석 OFF/실패:** 화면의 이유를 유지한다. 미탐지나 기관 승인을 통화 안전 판정으로 바꾸지 않는다. 외부 제공자 호출은 유효한 예산과 실행 허가 안에서만 한다.

이 안내에 비밀번호·키·토큰·쿠키를 기록하지 않는다. 실제 사용자 노트북의 음성·STT·분석 성공은 사용자가 촬영할 때 별도로 확인해야 한다.
