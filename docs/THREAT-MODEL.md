# 위협 모델과 신뢰 경계

기준일: 2026-10-27. 어떤 공격을 검사하고 누구를 여전히 신뢰하는지 정의한다. [구현 현황](guide/05-IMPLEMENTATION-STATUS.md)의 부분 구현·미실행 항목을 방어 완료로 취급하지 않는다. [통신 규약](PROTOCOL.md#protocol-profiles)에 코드 용어·형식 대응이 있다.

## 현재 서비스의 신뢰 출발점

등록 기관·콜센터 URI(식별 주소), 등록 키와 권한 원장을 신뢰 기준으로 사용한다. DID(분산 식별자)는 선택 호환 기능이다. 기관 승인 서비스(Issuer)와 콜센터 서명 서비스(Sender)가 서로 다른 키를 보유하고 플랫폼은 인증된 요청을 전달한다. 120초 최초 연결과 갱신형 통화 유지 허가를 구별한다. 목표 웹 통화의 실제 음성 종단은 Asterisk 교환기다.

## 공격자와 방어 요구

| 공격자가 시도할 수 있는 것 | 검사해야 할 경계·남은 한계 |
|---|---|
| 기관 표시 이름·승인서·위임 증서를 복사 | 등록 키 서명·고객·업무·목적·기간·권한 세대 검사. 콜센터의 요청별 키 소유 증명 필요 |
| 타 기관·다른 수신자·미할당 상담원의 객체 ID 사용 | 서버가 소속·역할·소유자·할당을 검사. 화면의 버튼 숨김이나 추측 어려운 ID는 접근 통제가 아님 |
| 승인·일회성 난수·키·협상 문서·현재 연결 바꿔치기 | 양측 서명과 실제 연결 관측을 대조. 필요한 관측이 없는 브라우저는 확인 불가 |
| 같은 승인을 동시 사용하거나 다른 API 형식으로 재사용 | 기관·승인 ID의 최초 결합을 DB에서 한 번만 고정. 동일 결합 재시도는 같은 영수증. 실제 PostgreSQL 경합 검증 전 |
| 취소·정지·키 교체 이전 상태를 재전송 | 현재 권한·세대·키와 최고 관측 상태 검사. 오래된 블록 재서명으로 최신성 연장 금지. 영속 기준·독립 anchor 대조를 구현했으며 재시작·전체 복원 실환경 검증 필요 |
| 증언자 하나의 거짓말·서명 중복·다른 블록 혼합 | 등록된 서로 다른 증언자 3개가 같은 체인·블록·상태에 서명해야 함. 정상 정족수의 공모는 별도 신뢰 위험 |
| 노드·증언자 지연·단절로 과거 상태만 제공 | 정족수 부족·오래된 증거·명시 철회를 구별. 새 연결 차단, 진행 통화는 확인 불가와 사용자 선택을 표시 |
| 다른 교환기 채널·브리지·통화 ID로 승인 전용 | 별도 PBX 서명과 양측 브라우저 보고·실제 채널 조회 대조. ARI 사건·권한 감시·철회·로그아웃·영속 회수에 연결했으며 실제 교환기 회수 미검증 |
| 일반 로그인으로 민감한 공식 업무 접근 | 공식 업무 용도·로그인 제공자/클라이언트·소유권 재검사. 접근할 수 없는 객체는 존재 여부를 숨기는 응답 |
| 전사문에 모델 지시를 넣거나 오래된 분석 결과 전송 | 전사문은 불신 입력, 모델 도구 실행 금지, 출력 형식·실제 발화·현재 수정 번호와 통화 ID 확인 |
| 동의 철회 후 오디오·늦은 모델 응답 재사용 | 동의 세대·열린 통화·유지 허가 검사, 작업 취소·전사/버퍼 폐기. 모든 제공자·브라우저 경로 검증은 남음 |

플랫폼 침해가 기관·콜센터 키 파일이나 `issuer_v2` DB 쓰기로 바로 이어져서는 안 된다. 다만 플랫폼이 전달하는 로그인 쿠키·CSRF 방지 토큰도 민감하다. 서비스 간 인증 비밀값은 사용자 인증을 대신하지 않는다. 내부망·승인 서비스 호스트 자체의 보호는 HTTPS·파일 권한·운영 통제에 의존하며 하드웨어 키 보관·서비스 간 상호 TLS를 구현했다고 주장하지 않는다.

## 음성과 분석의 신뢰

수신 브라우저가 상대 음성을 보내도록 구현하지만 악성 클라이언트가 제출 오디오를 바꾸는 것까지 서버가 증명하지는 못한다. 원음 기본 미보관은 CallSign의 정책이며 외부 제공자의 보관·학습 설정까지 보장하지 않는다. 분석은 읽기 전용 안내다. AI 장애·경고 없음은 안전 판정도 권한 철회도 아니다.

## 방어하지 못하거나 검증하지 않은 것

- 기관 승인자와 콜센터가 함께 침해돼 악성 연락을 승인하는 경우.
- 정상 권한의 상담원이 위험한 요구를 하는 행위 자체. 내용 분석은 보조 경고이며 예방 효과·정확도는 미측정이다.
- 정상 상태 증언자 정족수의 공모·공통 오동작, 신뢰 키 목록·웹 코드를 바꿀 수 있는 배포자, 침해된 수신 브라우저·OS.
- DB·키·백업 운영자의 권한 남용과 전체 상태를 과거로 복원하는 공격. 복원 대상 밖 최신 anchor·소비 journal 대조와 재개 gate를 신뢰한다. 이 독립 저장소까지 롤백/침해되거나 이력이 소실되면 자동 복구할 수 없다.
- 한 호스트의 여러 노드를 실제 독립 기관 운영이라고 해석하는 주장.
- 교환기 증언을 상담원 개인 신원이나 내부 음성 경로 전체의 무침해 증명으로 해석하는 주장.
- 실제 전화망·휴대전화 기본 앱·통신사 표시·착신전환·다자 회의. 현재 웹 교환기 경로와 별도 범위다.
- 미구현 체인 헤더·확정 서명·저장 상태 직접 검증 확장. 증언자 서명으로 대체 완료했다고 볼 수 없다.

## 초기 시연과 현재 정책의 차이

초기 시연은 기관명만 있는 연락을 `UNVERIFIED`(미확인), 서명·수신자·세션이 다른 연락을 `REJECTED`(거절)로 표시했다. 브라우저의 실제 인증서·데이터 채널과 최초 사용 DB 제약도 검사했다. 그러나 위임 철회 후 통화는 유지했다. 현재 기본 경로는 **명시적 철회 시 해당 통화 종료**를 권한 감시·교환기 회수·분석 취소에 연결했다. 실제 전파·회수 동작은 검증 전이다. [과거 시험](TEST-RESULTS.md)을 현재 방어 성공으로 재사용하지 않는다.

## 실행 전 보강한 경계

- 공동 설정 명령은 chain/contract·기관·종류·정확한 이전/다음 hash/version·epoch·nonce·deadline과 독립 키 2-of-3에 묶는다. 세 번째 중복/무효 서명도 거절하며 legacy directory 경로는 새 계약에서 닫는다. 제출 성공만으로 정책을 활성화하지 않는다.
- 내부 계정은 등록 issuer/정확한 subject로만 연결한다. 요청 인증 뒤 SQL transaction 안에서도 현재 membership generation·권한을 재검사한다. 일반 관리자의 자기 권한 상승·공동 승인자 임의 생성과 계정 재활성화 후 옛 세션 재사용을 차단한다.
- 권한 metadata checkpoint는 소비 외 계정/키/정책 변경과 취소 사건을 독립 anchor 이력에 결합한다. 일관된 과거 백업이 최신 권한처럼 복원되지 않도록 한다. DB/Issuer/anchor 관리자는 여전히 신뢰 대상이며 임의 악성 DB 쓰기 전체를 증명으로 검출한다고 주장하지 않는다.
- API/DB 장애에도 PBX 채널의 절대 timeout이 유지되도록 설정/조회한 뒤 음성을 허용한다. 실제 Asterisk 동작은 아직 시험하지 않았다. 관리 구성·개인키·PBX가 침해되면 이 보장은 깨질 수 있다.
- 웹 알림에는 전사/원음이 없고 계측 label은 고정 차원이다. 브라우저 duration은 비신뢰 단말 관측이다. 오프라인 증거는 비밀값·출력 크기를 제한하지만 공개 전에 별도 검토한다.


## 2026-10-30 영속 복구 시험으로 확인한 경계

[실행 평가](../artifacts/persistent-recovery-20261030.json)는 같은 서버의 다른 PostgreSQL 프로세스·volume·LOGIN과 HTTPS anchor에서 경쟁 CAS, 응답 유실, anchor/API/worker 재시작, journal 손상·오래된 DB 복원 차단을 확인한다. 앱 범위 복원에서 소비/철회/권한 세대를 보존하고 세션·미사용 승인·임시 연결을 폐기한다. 실제 체인 상태/전송과 통화는 fixture이며 검증 범위에 포함하지 않는다.

DB와 anchor의 분리 수명은 같은 호스트의 공동 침해·전원 손실·악성 저장소 관리자·독립 기관 운영을 방어했다는 증거가 아니다. 보호 ROOT와 backup key 소유자는 신뢰 대상이고 파일을 검사하는 동안 동시 악성 교체까지 방어했다고 주장하지 않는다. 기록 손상/anchor 선행 시 권한 부활을 막기 위해 가용성을 포기한다. 자동 정상화가 아닌 원본 이력 복구/공동 재신뢰 결정이 필요하다.
