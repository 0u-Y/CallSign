# 위협 모델과 신뢰 경계

기준일: 2026-10-27. 어떤 공격을 검사하고 누구를 여전히 신뢰하는지 정의한다. [구현 현황](guide/05-IMPLEMENTATION-STATUS.md)의 부분 구현·미실행 항목을 방어 완료로 취급하지 않는다. [통신 규약](PROTOCOL.md#protocol-profiles)에 코드 용어·형식 대응이 있다.

## 현재 서비스의 신뢰 출발점

등록 기관·콜센터 URI(식별 주소), 등록 키와 권한 원장을 신뢰 기준으로 사용한다. DID(분산 식별자)는 선택 호환 기능이다. 기관 승인 서비스(Issuer)와 콜센터 서명 서비스(Sender)가 서로 다른 키를 보유하고 플랫폼은 인증된 요청을 전달한다. 120초 최초 연결과 갱신형 통화 유지 허가를 구별한다. 목표 웹 통화의 실제 음성 종단은 Asterisk 교환기다.

## 공격자와 방어 요구

| 공격자가 시도할 수 있는 것 | 검사해야 할 경계·남은 한계 |
|---|---|
| 기관 표시 이름·승인서·위임 증서를 복사 | 등록 키 서명·고객·업무·목적·기간·권한 세대 검사. 콜센터의 요청별 키 소유 증명 필요 |
| 타 기관·다른 수신자·미할당 상담원의 객체 ID 사용 | 서버가 소속·역할·소유자·할당을 검사. 화면의 버튼 숨김이나 추측 어려운 ID는 접근 통제가 아님 |
| 승인·일회성 난수·키·협상 문서·현재 연결 바꿔치기 | 양측 서명과 실제 연결 관측을 대조. 필요한 관측이 없는 브라우저는 확인 불가 |
| 같은 승인을 동시 사용하거나 다른 API 형식으로 재사용 | 기관·승인 ID의 최초 결합을 DB에서 한 번만 고정. 동일 결합 재시도는 같은 영수증. 실제 PostgreSQL 경합 검증 전 |
| 취소·정지·키 교체 이전 상태를 재전송 | 현재 권한·세대·키와 최고 관측 상태 검사. 오래된 블록 재서명으로 최신성 연장 금지. 재시작·전체 복원 보완 필요 |
| 증언자 하나의 거짓말·서명 중복·다른 블록 혼합 | 등록된 서로 다른 증언자 3개가 같은 체인·블록·상태에 서명해야 함. 정상 정족수의 공모는 별도 신뢰 위험 |
| 노드·증언자 지연·단절로 과거 상태만 제공 | 정족수 부족·오래된 증거·명시 철회를 구별. 새 연결 차단, 진행 통화는 확인 불가와 사용자 선택을 표시 |
| 다른 교환기 채널·브리지·통화 ID로 승인 전용 | 별도 PBX 서명과 양측 브라우저 보고·실제 채널 조회 대조. 사건 처리·철회·로그아웃 자동 회수는 미완성 |
| 일반 로그인으로 민감한 공식 업무 접근 | 공식 업무 용도·로그인 제공자/클라이언트·소유권 재검사. 접근할 수 없는 객체는 존재 여부를 숨기는 응답 |
| 전사문에 모델 지시를 넣거나 오래된 분석 결과 전송 | 전사문은 불신 입력, 모델 도구 실행 금지, 출력 형식·실제 발화·현재 수정 번호와 통화 ID 확인 |
| 동의 철회 후 오디오·늦은 모델 응답 재사용 | 동의 세대·열린 통화·유지 허가 검사, 작업 취소·전사/버퍼 폐기. 모든 제공자·브라우저 경로 검증은 남음 |

플랫폼 침해가 기관·콜센터 키 파일이나 `issuer_v2` DB 쓰기로 바로 이어져서는 안 된다. 다만 플랫폼이 전달하는 로그인 쿠키·CSRF 방지 토큰도 민감하다. 서비스 간 인증 비밀값은 사용자 인증을 대신하지 않는다. 내부망·승인 서비스 호스트 자체의 보호는 HTTPS·파일 권한·운영 통제에 의존하며 하드웨어 키 보관·서비스 간 상호 TLS를 구현했다고 주장하지 않는다.

## 음성과 분석의 신뢰

수신 브라우저가 상대 음성을 보내도록 구현하지만 악성 클라이언트가 제출 오디오를 바꾸는 것까지 서버가 증명하지는 못한다. 원음 기본 미보관은 CallSign의 정책이며 외부 제공자의 보관·학습 설정까지 보장하지 않는다. 분석은 읽기 전용 안내다. AI 장애·경고 없음은 안전 판정도 권한 철회도 아니다.

## 방어하지 못하거나 검증하지 않은 것

- 기관 승인자와 콜센터가 함께 침해돼 악성 연락을 승인하는 경우.
- 정상 권한의 상담원이 위험한 요구를 하는 행위 자체. 내용 분석은 보조 경고이며 예방 효과·정확도는 미측정이다.
- 정상 상태 증언자 정족수의 공모·공통 오동작, 신뢰 키 목록·웹 코드를 바꿀 수 있는 배포자, 침해된 수신 브라우저·OS.
- DB·키·백업 운영자의 권한 남용과 전체 상태를 과거로 복원하는 공격. 복원 대상 밖 최신 기준·사용 이력과 안전한 재개 절차가 필요하다.
- 한 호스트의 여러 노드를 실제 독립 기관 운영이라고 해석하는 주장.
- 교환기 증언을 상담원 개인 신원이나 내부 음성 경로 전체의 무침해 증명으로 해석하는 주장.
- 실제 전화망·휴대전화 기본 앱·통신사 표시·착신전환·다자 회의. 현재 웹 교환기 경로와 별도 범위다.
- 미구현 체인 헤더·확정 서명·저장 상태 직접 검증 확장. 증언자 서명으로 대체 완료했다고 볼 수 없다.

## 초기 시연과 현재 정책의 차이

초기 시연은 기관명만 있는 연락을 `UNVERIFIED`(미확인), 서명·수신자·세션이 다른 연락을 `REJECTED`(거절)로 표시했다. 브라우저의 실제 인증서·데이터 채널과 최초 사용 DB 제약도 검사했다. 그러나 위임 철회 후 통화는 유지했다. 현재 목표는 **명시적 철회 시 해당 통화 종료**이며 이를 전체 교환기·분석 경로에 전파하는 구현과 검증이 남아 있다. [과거 시험](TEST-RESULTS.md)을 현재 방어 성공으로 재사용하지 않는다.
